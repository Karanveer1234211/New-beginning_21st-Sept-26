-------------------------------------------------------------------------------
 2. ONE-TIME SETUP
-------------------------------------------------------------------------------

 a) Install:

      pip install kiteconnect pyarrow pandas numpy pandas_market_calendars
      pip install yfinance          (optional - only for reconcile.py)

 b) Edit env_daily.bat. Set QUANT_HOME, CACHE_DAILY_ROOT, KITE_TOKEN_FILE.

 c) Create watchlist.txt - one symbol per line, no header:

      RELIANCE
      TCS
      INFY

    Do NOT add NIFTY 50, crude, gold etc. All 21 exogenous series are
    cached automatically on every run.

 d) First build. This is slow - Kite caps historical data at 3 requests
    per second, so ~1000 symbols takes a few hours. Run it overnight:

      call env_daily.bat
      python Daily_cache_v26.py --symbols-file watchlist.txt ^
             --start-date 2015-01-01 --end-date 2026-09-21 --force

 e) Verify before trusting anything:

      python data_quality.py --root %CACHE_DAILY_ROOT%

 f) Build the panel once in full:

      python panel_build.py --root %CACHE_DAILY_ROOT% ^
             --panel %CACHE_DAILY_ROOT%\panel --full

 g) Schedule daily_run.bat in Task Scheduler for 23:45, weekdays.
    Action = Start a program. Program = the full path to daily_run.bat.


-------------------------------------------------------------------------------
 3. DAILY
-------------------------------------------------------------------------------

 ONE command. Scheduled, or by hand:

      daily_run.bat

 It runs three stages and STOPS at the first failure:

      1. CACHE    fetch raw OHLCV: equities + 21 exogenous series
      2. GATE     calendar, session gaps, absence classes, quarantine
      3. PANEL    incremental panel update

 Exit 0 only if all three succeeded. Exit non-zero is logged as FAILED in
 daily_run.log. A run that does not build a panel is not a success.

 TIMING - run after 23:45 IST. MCX trades to 23:30.

 Running EARLIER is safe. Each series is clamped to its own last CLOSED
 session, so no partial candle ever reaches disk:

      run at 14:00  ->  NSE=yesterday  CDS=yesterday  MCX=yesterday
      run at 16:30  ->  NSE=TODAY      CDS=yesterday  MCX=yesterday
      run at 17:30  ->  NSE=TODAY      CDS=TODAY      MCX=yesterday
      run at 23:50  ->  NSE=TODAY      CDS=TODAY      MCX=TODAY

 An early run simply gets fewer bars. Run again later and it fills in.

 RUNNING AGAIN the same evening costs almost nothing - daily_run.bat passes
 --only-stale, so symbols already current are skipped entirely (0 API
 calls). The panel updates incrementally either way.

 Equivalent by hand:

      call env_daily.bat
      python run_daily.py --symbols-file watchlist.txt --only-stale

-------------------------------------------------------------------------------
 5. OCCASIONAL
-------------------------------------------------------------------------------

 CROSS-CHECK AGAINST AN INDEPENDENT VENDOR - monthly, or after anything odd:

      python reconcile.py --root %CACHE_DAILY_ROOT% --sample 100

 Compares RETURNS (not price levels - vendors use different adjustment
 bases) against Yahoo. Catches missed splits, bad prints, missing sessions.
 A disagreement identifies a conflict, not a culprit: check the NSE
 bhavcopy before assuming the cache is the wrong one.

 FULL PANEL REBUILD - after changing feature definitions:

      python panel_build.py --root %CACHE_DAILY_ROOT% ^
             --panel %CACHE_DAILY_ROOT%\panel --full

 Also happens AUTOMATICALLY whenever the allowed universe changes, because
 cross-sectional ranks depend on who is in the universe on each date.

 SEE WALK-FORWARD FOLDS:

      python panel_build.py --root %CACHE_DAILY_ROOT% ^
             --panel %CACHE_DAILY_ROOT%\panel --splits 5

 REPAIR ONE BAD SYMBOL:

      python Daily_cache_v26.py --symbols RELIANCE --force ^
             --start-date 2015-01-01 --end-date <today>


-------------------------------------------------------------------------------
 6. ENVIRONMENT VARIABLES
-------------------------------------------------------------------------------

 CACHE_DAILY_ROOT        where parquet files live
 KITE_TOKEN_FILE         Kite access token JSON

 CACHE_HISTORY_ANCHOR    earliest stored date, e.g. 2015-01-01
                         *** SET ONCE, THEN NEVER CHANGE IT ***
                         The expanding-rank WQ alphas are computed from the
                         first stored row. Moving this changes their values
                         for dates already cached, and invalidates every
                         model trained on the old values.

 CACHE_REFETCH_TAIL_DAYS trailing sessions refetched each run (default 7).
                         Picks up vendor corrections.

 CACHE_WARMUP_DAYS       calendar days of warm-up (default 520). Needs to
                         cover 252 + 60 bars. Lower it and long-window
                         features silently stop converging.

 CACHE_SESSION_GRACE_MIN minutes after session close before a bar counts as
                         final (default 15).

 PARQUET_ENGINE          pyarrow
 PARQUET_COMPRESSION     snappy

 7. WHEN IT FAILS
-------------------------------------------------------------------------------

 "QUARANTINE: not building a panel on this data"
   The gate rejected something. Open quarantine.json and read the reasons.
   Then either fix it (--force that symbol) or accept a thinner universe
   for today with:  run_daily.py ... --allow-partial
   Do NOT disable the gate.

 "N isolated sessions missing with no market-wide or suspension explanation"
   Real data loss. --force that symbol.

 "NIFTY50 is the panel's master calendar. Do not build a panel until it is
 current."
   Everything downstream depends on it. Fix this before anything else.

 "calendar is single-sourced (untrusted)"
   Fewer than 2 independent calendar sources. Install
   pandas_market_calendars, or cache more symbols (consensus needs 10+).

 "completeness NOT verifiable: no peer series on this exchange"
   USDINR is alone on CDS, so nothing can audit it. Cache a second CDS
   contract, or pass --allow-unverified if it is context rather than signal.

 "N split-shaped discontinuity(ies)"
   A corporate action was detected. The cache refetches the symbol whole.
   If it persists, check the split date against NSE.

 "AlphaComputationFailed"
   A WorldQuant alpha raised. Probably a pandas upgrade. Do not ignore it -
   these used to fail silently into all-NaN columns.

 "UnknownRollFilled"
   Something filled D_roll NA with 0. NA means "we do not know whether this
   bar crosses a futures roll" and filling it fabricates that knowledge.

 "STATIC LEAK CHECK FAILED"
   You added a construct that can read the future. If it is genuinely safe,
   annotate the line with "# leak-free: <why>" and state the reason.

 "ContractIncomplete"
   A new feature has no entry in FEATURE_HYPOTHESIS. Add one. A feature with
   no stated purpose cannot be defended in an importance ranking.

 "UNIVERSE CHANGED ... Forcing a FULL rebuild"
   Not an error. Expected whenever a symbol enters or leaves the gate.

 Auth errors at 23:45
   The Kite token expires daily. Refresh it before the scheduled run or the
   job dies at authentication.


-------------------------------------------------------------------------------
 8. THINGS NOT TO BREAK
-------------------------------------------------------------------------------

 * Build X with panel_feature_columns(panel). NEVER with panel.columns.
   ret_5d_close_pct and every label_* column are forward-looking.

 * The last 5 sessions of the panel have NO label. They are UNKNOWN, not
   negative. Filling them with 0 teaches the model that recent weeks never
   move.

 * Embargo >= 5 sessions between train and test, always. A row dated t
   carries an outcome resolving at t+5.

 * Daily features resolve at session t's 15:30 close and are usable from
   session t+1's 09:15 open. NOT at 15:29 on day t. This matters when
   feeding them to the ORB model.

 * Never read the cache parquet directly in model code. Use
   load_cached_symbol() or panel_build, which strip warm-up and labels.

 * Macro series (crude, gold, USDINR) are lagged one session automatically
   because they close after NSE. Do not remove that lag.


-------------------------------------------------------------------------------
 9. WHAT THIS PIPELINE DOES NOT SOLVE
-------------------------------------------------------------------------------

 Stated plainly so it is not mistaken for coverage:

 * SECTOR MEMBERSHIP is not point-in-time. Sector-relative features are
   deliberately absent. A sector map scraped today and applied to 2019 is
   both lookahead and survivorship bias, in the feature family most likely
   to carry real cross-sectional alpha. --sector-map is the hook.

 * FUTURES ROLL HISTORY before your first run is unknown. Kite's instrument
   dump holds live contracts only, so the roll calendar grows forward from
   today. D_roll is NA for older bars and the gate refuses them.

 * VENDOR ACCURACY is only checked when you run reconcile.py, and only
   against Yahoo. Neither is a reference standard.

 * PUBLICATION-TIME LAG for revised data is not modelled. Every series here
   is exchange price data, where publication is the close. The day you add
   something that gets revised, this becomes a real gap.

 * The tests prove the arithmetic and the causality of the FEATURE layer.
   They cannot prove the model is assembled at the right point in time
   across the right universe with the right train/test boundaries. That is
   the next thing to get strict about.
